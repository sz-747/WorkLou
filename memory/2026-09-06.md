# WorkLou Session Memory

## Decisions

- Keep provider calls to reusable volatile service facts: current wait time for every service and current capacity for accommodation. Durable profile facts belong to background online enrichment because repeating case-specific calls increases caseworker notes and documentation load.
- Treat Watershed as explicitly synthetic demo data and keep its seed aligned with the synthetic CSV rather than presenting fixture assumptions as real provider evidence.
- Keep Bright Data Web Unlocker out of the demo. A blocked provider page is a logged source failure; the demo only needs the updater and discovery background processes to run visibly.
- Finish the backend-to-Base44 bridge sequentially before beginning the Figma UI integration.
- Keep Postgres canonical and use two thin Base44 scheduled functions to call the existing protected updater and discovery routes. Activate the schedules only after both manual Base44 runs pass.
- Treat Base44 scheduler activation as optional for the hackathon UI handoff. The demo can show clearly labelled stored demo activity or manual-run progress; do not present an inactive schedule as live.
- Keep intake notes and extracted Postgres-aligned facts together on one 4:1 screen; start deterministic service ranking as soon as extraction finishes.
- Rank and show the top three services with a transparent 100-point calculation: needs 40, eligibility 35, location 15, evidence freshness 10. Keep mismatches visible as trade-offs so the caseworker retains judgment.
- Approval of a prepared referral records it in WorkLou Follow-ups; the demo does not transmit external email.
- Keep Docker for Postgres only during UI tweaking. Run the Next.js dev server directly on Windows to avoid bind-mount latency.
- Remove victim-facing Quick Exit and generic client footer links; active client screens show only the person currently being worked with.
- Keep the five-step referral journey central on each person profile and on the service plan. Follow-ups is a separate, filterable history of referral emails and recorded actions.
- Treat the sage-green vertical workflow as stale: active routes redirect to the warm white A2 interface, which uses dim-orange and dusty-blue glass accents.
- Keep new-call intake one click from the shared top bar. The Today rail shows background service fact changes and newly discovered services from Postgres, not accommodation availability.
- In development, move the nav marker immediately and prefetch dashboard routes because the first Turbopack compile can dominate click latency even when Postgres reads are fast.
- The Services/Shelters tab is a person-specific ranked top-three decision workspace, not a raw services table. Show email and phone together, and direct workers to call when details or email are missing.
- Store Hannah Lee's caseworker email in Postgres Settings and add it to referral signatures. The worker edits and copies the draft in WorkLou, sends it from a pre-addressed Gmail Compose popup, then explicitly marks it sent so Follow-ups records it.
- Keep the hackathon presentation local-first rather than moving the current dashboard into Base44. Demo documents can live as local static files served by Next.js.
- Keep profile actions in their relevant sections: Top referrals directly below Recent contact, support letters inside Files, and the close action inside a small Profile options card.
- After intake extraction, approve the exact new profile and open its referral profile through Review Top 3 Referrals. Lead with income, languages, children and pets; show rank one large beside ranks two and three, with strengths and trade-offs drawn from the deterministic 100-point matcher.
- Recognize caseworker impact with Today and month totals, a 365-day orange activity grid, and four local-demo achievement medals that flip to show earned dates. Use large contribution squares and orange scrollbars; remove the old root navigation globally so only the active glass dashboard shell appears.
- On People, show the newest extracted Focus immediately, derive Stage from the latest referral state, and use explicit AM/PM contact times plus concrete ordinal follow-up dates so the row stays readable as casework changes.
